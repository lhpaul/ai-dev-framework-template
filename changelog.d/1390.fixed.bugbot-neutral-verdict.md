- **The reviewer loop no longer reports `RESULT=clean` for a Cursor Bugbot run that concluded `neutral`** (#1390): `neutral` is what Cursor posts both for a review that found nothing and for one that found blocking issues, so the check-run conclusion was never a verdict — a merge was authorised on "reviewer clean" while three findings, two of them High severity, sat in `cursor[bot]` comments. `run_bugbot_review` now carries the check run's `output.summary` alongside the conclusion and treats the `neutral|cancelled|skipped` conclusion as unproven: it parses the summary for a `found N potential issues` / no-issues verdict and fetches the `cursor[bot]` comments and reviews for the head, so retrievable findings report `RESULT=needs_fixes` (`REASON=blocking_findings`) with `BLOCKING_<i>_PATH` / `_LINE` / `_BODY` detail. An absent or unrecognised summary escalates as `REASON=bugbot-unverified-verdict`; findings the summary reports but the API does not return escalate as `REASON=bugbot-findings-not-retrievable` — the previous default failed in the unsafe direction. `is_bugbot_clean_review` now recognises any positive finding count rather than only 1–5. Separately, an unfinished check run is re-triggered once with the trigger comment before the loop declares a timeout, so an intermittent Bugbot stall no longer surfaces as a `reviewer-failed` label that reads like a finding.
