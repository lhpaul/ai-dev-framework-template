- **Planted-violation proof for trigger- or gate-only changes** (#2115): `REVIEW.md` (rule and code review checklist), `docs/best-practices/3-testing.md` and the test-scope proportionality guide now describe how to prove a change that only alters *when* an existing check runs (event types, path or branch filters, job-level `if:`). Such a change keeps the check's existing proof and is proven with live runs in both directions that differ only in the input the gate keys on, citing each gate location and the run IDs (or, when a workflow-level filter skips the check and no run is created, the commit with its empty run listing), instead of a failing-check run. The checklist says how reviewers recognise the case from the diff, so the local AI reviewer no longer asks for a failing check that cannot exist.
