- **An agent can no longer silently edit a sibling's pull request in a parallel wave** (#1444): the new `scripts/development-workflow/pr-ownership-guard.sh` resolves a PR's head branch and head repository and exits `0` only when both belong to the item. It refuses a mismatched number, or a fork PR that reuses the branch name, with `RESULT=not_owned`, and fails closed when the PR or the current branch cannot be resolved. `pr-review-loop.sh` now runs the same check on every run before any side effect: against `--branch` when given, otherwise against the workflow branch checked out in `--repo-root` or the working directory. It stops with `RESULT=escalate` (exit `2`) instead of commenting on, readying, or labelling another PR: `REASON=pr_ownership_mismatch` for a PR of another branch or repository, `REASON=pr_ownership_unverified` when the PR or target repository cannot be resolved, and `REASON=pr_ownership_branch_required` when no `--branch` is given and the checkout is detached or on `develop`, `main`, or another non-workflow branch. The check inspects the same target repository as the loop's lock key, which now also honours `GH_REPO`, so a shell that exports `GH_REPO` gets a lock name for that repository. Protocols 01, 02, and 03 require the guard before every `gh pr edit`, `gh pr comment`, `gh pr ready`, `gh pr close`, or label change by number. Protocols 90 and 91 give each parallel agent a private scratch directory with collision-proof filenames such as `pr-body-<item>-<pid>.md`, and ask for review-gate evidence to be mirrored as a PR comment, since a PR description can be overwritten silently.
