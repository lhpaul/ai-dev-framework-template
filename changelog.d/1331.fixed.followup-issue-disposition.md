- **Follow-up issues are classified before merge so deferred ones stay open** (#1331): `item-completion-self-check.sh` accepts repeatable `--followup <issue>=<fixed|deferred>` and prints a `followup.#<N>` row per issue. A `deferred` follow-up that is already closed, or that the PR title, body or commit messages close with a closing keyword (read the way `post-merge-cleanup.sh` reads them), is a `discrepancy`; one whose state cannot be read is `unavailable_required`. The helper detects violations; it cannot know which follow-ups were filed, so the runner must enumerate them all. Protocol 91 requires the runner to enumerate every filed follow-up as "fixed in this PR" or "deferred to future PR", to close only the former, and to keep the dispositions in the merge and cleanup completion records.
