- **`add-backlog-item.sh create`: verify project-field writes instead of trusting a 200 response** (#1778): Status/Type/Size updates (`ensure_on_project_board`, `update_tracker_type_best_effort`, `update_tracker_size_best_effort`) previously always returned success even when the GraphQL write silently did not land — the same fail-open pattern #965/#1183/#1191/#1501 each patched for one field at a time. `update_tracker_type_best_effort` now accepts a `required` mode and `update_tracker_size_best_effort` always runs required, so a dropped write is a loud, non-zero failure. `create` also re-reads the created item after every write (with a short bounded retry for GitHub Projects' read-after-write lag) and compares Status/Type/Priority/Size against what was requested, exiting 5 with the specific mismatch(es) when the board does not actually show the requested value. The hardcoded `'Type'` wording in the "has no Type value" warning now honours `issue_tracker.custom_fields.type_field`.
