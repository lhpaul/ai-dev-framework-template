- **`add-backlog-item.sh create`: verify project-field writes instead of trusting a 200 response** (#1778): Status/Type/Size updates (`ensure_on_project_board`, `update_tracker_type_best_effort`, `update_tracker_size_best_effort`) previously always returned success even when the GraphQL write silently did not land — the same fail-open pattern #965/#1183/#1191/#1501 each patched for one field at a time. `update_tracker_type_best_effort` now accepts a `required` mode and `update_tracker_size_best_effort` always runs required, so a dropped write is a loud, non-zero failure. `create` also re-reads the created item after every write and compares Status/Type/Priority/Size against what was requested, exiting 5 with the specific mismatch(es) when the board does not actually show the requested value; a bounded retry re-issues the actual write (not only the read) for GitHub Projects' read-after-write lag on a just-added item, and Status is only enforced when this invocation is the one that added the item to the board. The hardcoded `'Type'` wording in the "has no Type value" warning now honours `issue_tracker.custom_fields.type_field`.
