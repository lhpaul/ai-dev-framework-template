- **Every CI consumer now judges only the latest run of each check** (#1559): GitHub's `statusCheckRollup` keeps superseded runs, so a check that failed and then passed on re-run (PR #1547: `policy failure 05:26:31`, `policy success 05:28:16`) could read as a current failure. The deduplication now lives in one place, `STATUS_CHECK_ROLLUP_DEDUPE_JQ` / `normalize_status_check_rollup` in `workflow-lib.sh`. `pr-ci-loop.sh`, `pr-review-loop.sh`, `item-completion-self-check.sh`, `batch-merge.sh`, `discover-workflow-state.sh`, `run-epic-risk-classifier.sh`, and `run-epic-delegated-gate.sh` all use it, replacing three inline copies and two divergent implementations. The delegated merge gate no longer blocks a healthy PR on a superseded failure. The risk classifier no longer merges same-named jobs from different workflows, which could hide one workflow's failure behind the other's success. A queued re-run now counts as the latest run instead of sorting behind the result it replaces. Protocols 90 and 91 now state that "0 non-green checks" counted over the raw rollup is not a readiness assertion.
