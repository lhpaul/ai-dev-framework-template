- **Scope resolver separates a failed PR lookup from "no PR"** (#1805): `run-epic-scope-resolver.sh` returned empty `pullRequests` arrays both when no PR existed and when its fallback `gh search prs` / `gh pr view` calls failed (rate limit, network error). Each scope item now carries `prEvidenceUnavailable` (`true` when the lookup could not complete or never ran, as in the Linear deferred placeholder), while `pullRequests` keeps its `{open, merged}` shape and a scope without the field reads as `false`. The `/run-item` framework-mode Backlog-routing gate (#1583) now reads that flag as `unavailable` evidence instead of `none`, so a failed PR search no longer stops an item that is already in progress. Regression coverage in `tests/test-run-epic-scope-resolver.sh`, `tests/test-framework-mode-type-routing.sh` and `tests/test-run-bounded-prelude.sh`.
