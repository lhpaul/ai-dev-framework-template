- **`feat/` branches are now recognised as `feature/`** (#1401): `branch_prefix` resolved `feat/*` to `unknown`, so such a branch was never deleted by `post-merge-cleanup.sh`, received no reviewer from `reviewer_for_branch` (no code review from the loop), and took the wrong repository context and `NEXT_ACTION` in `workflow-next-action.sh`. `feat/` is now an alias of `feature/` in `workflow-lib.sh`, which fixes every consumer that switches on `branch_prefix`. The two issue-number parsers that match branch names directly (`workflow-next-action.sh` and `post-merge-cleanup.sh`) accept `feat/` too, so hub-only routing and the Merged/close tracker path work for `feat/<n>-…` branches. `chore/`, `docs/`, `cursor/` and `haystack/` stay `unknown` by design; scripts that still match `feature/*` literally are outside this fix. The change only affects future cleanups and deletes nothing retroactively. Regression coverage in `tests/test-workflow-lib-branch-prefix.sh`, `tests/test-workflow-orchestration-product-repo-aware.sh` and `tests/test-post-merge-cleanup.sh`.
