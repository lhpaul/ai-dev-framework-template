- **Add matrix coherence preflight for spec reviewer loops** (#1759): specs, implementation plans, and Refactor work item briefs that contain a decision matrix, state table, lifecycle, precedence rules, or similarly stateful contract now carry a mandatory six-check coherence audit — overlapping rows, missing states, precedence/order ambiguity, malformed/unknown input handling, stale-vs-current evidence, and terminal/waiting/escalation outcome coverage. Protocol 01's Document Quality Gate section carries the canonical six-check definition and runs the audit before the spec's first push; Protocol 02's cross-section consistency self-check extends it to a plan's own stateful contracts and Refactor briefs. When a reviewer loop's blocking findings implicate the same matrix across two consecutive cycles, Protocol 93's "Long spec/plan review-cycle guidance" now requires the loop runner to re-run the audit before the next fix push and record the result in the fix commit comment; Protocol 91's stuck-loop escalation rules always evaluate first and the re-audit never extends a cycle cap. A `Matrix coherence preflight` row in the Document Quality Gate log — `Checked` with an audit summary, or a reasoned `Not applicable — no stateful contract` — is now required by `REVIEW.md`'s Spec and Plan Review Checklists; a misclassified `Not applicable` row on an artifact that actually has a stateful contract is a blocking finding. Adds a new `Stateful-contract outcome gaps` pattern to `review-doctrine.md` covering the three checks not already named by the existing `Criteria/matrix mismatch` and `Trigger ambiguity` patterns. Implementation PRs remain out of scope — the preflight gates spec and plan artifacts only. Fifteen agent/skill mirror files under `.claude/agents`, `.cursor/agents`, and `.codex/skills` point at the new gate.
