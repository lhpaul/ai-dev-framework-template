- **The expensive-reviewer gate no longer deadlocks on the loop's own
  completion guard** (#1879): `pr-review-loop.sh` no longer counts the
  `Reviewer-loop completion guard (#<pr>)` commit status when it checks that
  the PR's other checks are green. That status stays red until the loop posts
  a clean summary, and the loop needs the gate to pass before it can post one.
  A PR whose first run ended `needs_fixes` was stuck on
  `baseline_checks_not_green` even after every real check passed. Any other
  failing check still holds the gate. `pr-ci-loop.sh` keeps counting the guard,
  because a red guard there means the review is not clean.
