- **PR policy no longer goes red before the reviewer loop has posted** (#1838): on `pull_request_target` events, the `Reviewer-loop completion guard (#N)` status is now `pending` and the `policy` job exits 0 in two cases. The first is a missing summary, at `ready_for_review` before the loop's first post. The second is a clean summary recorded for an older head, at `synchronize` after a push. The loop's `workflow_dispatch` run still sets the status to `success` or `failure` once it posts. A non-clean latest summary, a skipped hotfix summary, a clean summary with no head history, and PR or comment fetch failures still fail with exit 1. A pending status still blocks readiness.
