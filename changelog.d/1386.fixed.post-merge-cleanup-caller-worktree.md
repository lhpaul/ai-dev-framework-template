- **`post-merge-cleanup.sh` no longer deletes the calling runner's own worktree** — when the merged branch is checked out in the caller's worktree (the one named by `--repo-root`, or the one the helper is invoked from), cleanup now detaches that worktree onto the updated base and then deletes the branch, instead of force-removing the directory the runner is running in. Without `--repo-root`, the helper now uses the calling worktree rather than defaulting to the main clone. If uncommitted changes block the detach, cleanup leaves the worktree and branch in place (`LOCAL_DELETE_RESULT=skipped`) and still finishes the tracker updates. (#1386)
