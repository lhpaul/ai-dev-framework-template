- **`apply-readiness-labels.sh` gained `--dry-run` and a PR ownership guard** (#1837): running the helper "to check" previously applied the readiness label for real — an informational call mutated PR #1825 ahead of its planned order. `--dry-run` now runs the full gate (ownership, reviewer, and CI checks) against live state and reports the verdict — `RESULT=would-label` in place of `labeled`, plus `refused`/`escalate` unchanged — without calling `gh pr edit` at all: no label add, no stale-label removal, no `needs-fixes` annotation. Every verdict now also carries `DRY_RUN=true|false`. Before reading any further PR state, the helper also verifies the PR belongs to the caller: a new `--branch <branch>` option (defaulting to the branch checked out in the repo root, mirroring the `pr-review-loop.sh --branch` guard from #1444) is checked against the PR's actual head branch and head repository via the existing `pr-ownership-guard.sh` helper. A mismatch — for example a transposed `--pr` under a parallel wave labelling a sibling's PR — refuses `REASON=ownership-mismatch` before any state read; an unresolvable check (an unreadable `gh pr view`, or no `--branch` on a detached/non-workflow checkout) escalates `REASON=ownership-unverified`, never a silent pass. New tests in `scripts/development-workflow/tests/test-apply-readiness-labels.sh` (Area 18) cover both: a clean dry run, a refusing dry run that still removes nothing (including an existing stale label), a branch mismatch, a cross-repository PR reusing the branch name, an unresolvable ownership check, and the matching-branch positive path.
