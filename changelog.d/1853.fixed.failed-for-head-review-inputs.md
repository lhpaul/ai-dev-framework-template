- **A description-only fix no longer needs an empty commit to be re-reviewed** (#1853): `pr-review-loop.sh` refused any re-review on a head where the second local pass had failed (`REASON=failed_for_head`), including a `needs_fixes` result whose fix was a PR description edit, so the only way through was an empty commit that reset head-bound evidence. The refusal is now keyed on the head and the review inputs: a `needs_fixes` failure records the review-evidence fingerprint (PR body and eligible conversation comments) it saw, and a later run on the same head re-reviews once that fingerprint changes (`LOCAL_SECOND_PASS_REASON=review_inputs_changed`). An infrastructure failure (timeout, crash, unavailable pass) allows exactly one automatic retry on the head (`infrastructure_retry`). Each such automatic re-review spends a reviewer-loop cycle on both caps. An unchanged head with unchanged inputs still refuses, as do legacy ledger records and unreadable evidence. Regression coverage in `tests/test-pr-review-loop-staged-gates.sh`.
