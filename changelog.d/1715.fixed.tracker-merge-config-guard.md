- **`update-tracker-on-merge.yml`: skip cleanly when GitHub Projects is not configured** (#1715): the tracker-update step passed `github-token: ${{ secrets.GH_PROJECT_TOKEN }}` to `actions/github-script`, whose `github-token` is a required input — so a repository generated from this template that had not yet configured a project board failed with `Input required and not supplied: github-token` on **every** merge to `develop`, before the existing in-script `PROJECT_NUMBER` guard could run. Adds a `Check tracker configuration` step that reads the secret into `env` (the `secrets` context is unavailable in step-level `if:`) and exposes a `configured` output; the tracker-update, graduation-checkout, and graduation-closeout steps now gate on it and skip with a job warning and step-summary note instead of failing the check. `check-tracker-merge-mapping.sh` asserts the gate stays wired — every step consuming `secrets.GH_PROJECT_TOKEN` must be gated, and the gate step must exist whenever the secret is referenced — with planted-violation coverage in `test-check-tracker-merge-mapping.sh` for an ungated consumer and for a deleted gate step. Documents `GH_PROJECT_TOKEN`, `PROJECT_NUMBER`, and `PROJECT_OWNER` as an explicit bootstrap step in `docs/workflow/development-workflow/integrations/github-projects.md`, correcting the stale `GITHUB_PROJECT_NUMBER` / `GITHUB_PROJECT_OWNER` variable names and the incorrect claim that no PAT is required.
