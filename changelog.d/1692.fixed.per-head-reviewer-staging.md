- **Reviewer loop no longer re-runs reviewers already clean on the current head** (#1692): when the persisted reviewer-loop ledger already records a configured reviewer clean on the pull request's current head, later cycles on that same head replay that verdict instead of dispatching the reviewer again. The replay carries the same head evidence, peer evidence, and ledger record a dispatch would have, so every downstream gate is unchanged. Any other evidence state — missing, unparseable, not clean, or reviewed on a different head — still dispatches, and a new head clears every skip, so the local reviewer runs again before ready-phase reviewers resume.
