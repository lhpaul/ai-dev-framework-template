- Readiness labels (`ready-for-human-review`, `ready-for-regression`) can no longer be applied on an agent's judgement alone. The new `scripts/development-workflow/apply-readiness-labels.sh` refuses to apply either label unless every configured ready-phase reviewer check run is `completed` for the current head SHA, the reviewer posted no blocking findings on that SHA, and no non-reviewer check is pending or failing. An absent reviewer check run counts as **not** clean, so a reviewer that refused to run never reads as a clean verdict. Findings come from `pulls/N/comments` and `pulls/N/reviews`, never from issue comments.
- Protocols 91 (Step 7b, Step 8a) and 95 (Step 8) now state that agents must not call `gh pr edit --add-label ready-*` directly and must route readiness through the helper, whose `RESULT=refused` verdict is a stop rather than a warning.
- `workflow-lib.sh` gains `normalize_status_check_rollup()` (the `statusCheckRollup` duplicate-collapsing normalization `pr-review-loop.sh` and `pr-ci-loop.sh` each carried inline) and `bot_login_for_platform()`, so readiness gating and the completion self-check resolve reviewer logins from one place. No existing caller is changed by either addition.
