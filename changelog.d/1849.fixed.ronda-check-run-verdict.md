- **The Ronda reviewer adapter now reads its verdict from the check-run summary, not the conclusion** (#1849): Ronda's `success` conclusion means the pass completed, with or without findings, and `failure` means the pass could not complete. `run_ronda_review()` in `pr-review-loop.sh` treated them as clean and blocking findings, so a pass with Blocking findings read as clean, and a pass failure (for example a missing credential) sent the fixer after findings that did not exist. The adapter now parses the summary's `Blocking: N, Important: N, Nit: N` line. `Blocking: 0` is clean with Important and Nit counted as suggestions. `Blocking: N` (N ≥ 1) is `needs_fixes`. A missing, duplicated, or malformed line escalates as `ronda_severity_unparseable`, and a second malformed `Blocking:` line cannot hide behind a valid one. `failure` escalates as `ronda_pass_failed` and carries the check-run title. `action_required` now escalates as an unexpected conclusion. The verdict no longer depends on the `ronda[bot]` review-author lookup, which never matched reviews posted by Ronda's GitHub Actions workflow as `github-actions[bot]`.
