- **`backport/*` branches are now a recognised branch class** (#2158): `branch_prefix` resolved `backport/*` to `unknown`, so `post-merge-cleanup.sh --inspect-targets` classified a product-repository backport PR as hub-owned and searched for it in the workflow hub, `workflow-merge-budget.py begin` stayed `Deferred`, and no PR on a `backport/*` branch could be merged through the delegated path. `workflow-lib.sh` now returns `backport` for `backport/<remainder>` (a bare `backport` or `backport/` stays `unknown`) and treats it as an implementation-branch class (adopting the consumer-approved Option A): `post-merge-cleanup.sh` classifies it as an implementation branch (product-repository selection, exact-PR remote cleanup), `reviewer_for_branch` assigns `code-reviewer`, and the four `workflow-next-action.sh` routing sites route it like `feature|refactor|fix|hotfix`. Issue-number parsing is unchanged: a backport PR re-carries already-shipped work and does not close or advance an item. Scripts that still compare branch prefixes literally stay tracked by #2146.
