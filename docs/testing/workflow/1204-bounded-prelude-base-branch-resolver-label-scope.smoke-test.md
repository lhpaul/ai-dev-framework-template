## Smoke Test Steps

### Step 1: Run Resolver Regression Harness

**Maps to**: Acceptance Criteria 1, 2, 3, 4, 5, 6, 7, 9, 10

1. Run:

   ```bash
   bash scripts/development-workflow/tests/test-run-epic-scope-resolver.sh
   ```

2. Verify the output includes passing assertions for:
   - no-label explicit-list base selection;
   - partial-label fallback warning;
   - mixed-label fallback warning;
   - valid shared-label branch validation;
   - missing shared-label branch fallback;
   - remote validation failure fallback;
   - no mutating GitHub commands.

**Expected result**: The test harness exits `0`, and every added resolver
assertion reports `ok`.

### Step 2: Run Bounded Prelude Summary Harness

**Maps to**: Acceptance Criteria 7, 8

1. Run:

   ```bash
   bash scripts/development-workflow/tests/test-run-bounded-prelude.sh
   ```

2. Verify the output includes passing assertions that the confirmation summary
   exposes the selected base, base reason or source, resolver warning when
   fallback occurs, and the read-only guarantee.

**Expected result**: The test harness exits `0`, and the bounded prelude summary
shows the fallback reason before any mutation can happen.

### Step 3: Run Shell Quality Gates

**Maps to**: Acceptance Criteria 6, 7, 10

1. Run:

   ```bash
   python3 scripts/lint/workflow-shell-guard-lint.py --base-ref origin/develop
   ```

2. Run:

   ```bash
   shellcheck \
     scripts/development-workflow/run-epic-scope-resolver.sh \
     scripts/development-workflow/run-bounded-prelude.sh \
     scripts/development-workflow/tests/test-run-epic-scope-resolver.sh \
     scripts/development-workflow/tests/test-run-bounded-prelude.sh
   ```

**Expected result**: Both commands exit `0`.

### Step 4: Inspect Read-Only Behavior

**Maps to**: Acceptance Criterion 7

1. Review the resolver harness call log generated by
   `test-run-epic-scope-resolver.sh`.
2. Confirm it contains no `issue edit`, `pr create`, `pr merge`,
   `project item-edit`, `project item-add`, or GraphQL mutation calls.

**Expected result**: The resolver only reads issue labels, PR state, repository
mode, and remote refs.

### Step 5: Validate Documentation

**Maps to**: Acceptance Criteria 8, 9

1. Open the updated bounded prelude and run-items/run-epic guidance.
2. Confirm the docs describe:
   - explicit-list partial labels falling back to `develop`;
   - mixed labels falling back to `develop`;
   - shared labels requiring branch validation before adoption;
   - validation failures being visible before mutation.

**Expected result**: Documentation matches the implemented resolver behavior.

## Assertions Checklist

- [ ] Explicit-list batches with no integration labels resolve to `develop`.
- [ ] Explicit-list batches with partial integration-label coverage resolve to
      `develop` and emit a partial-label warning.
- [ ] Explicit-list batches with mixed integration labels resolve to `develop`
      and emit a mixed-label warning.
- [ ] Explicit-list batches with one shared valid integration label may resolve
      to `develop-<slug>` only after branch validation succeeds.
- [ ] Explicit-list batches with one shared stale integration label resolve to
      `develop` and emit a missing-branch warning.
- [ ] Remote validation failures do not silently adopt an integration branch.
- [ ] The bounded prelude remains read-only.
- [ ] The operator-facing summary includes selected base and selection reason.
- [ ] Single-item or epic-scoped integration-label behavior remains compatible
      while avoiding silent adoption of a missing remote branch.
- [ ] Automated regression coverage includes no-label, partial-label,
      mixed-label, valid-shared-label, and stale-shared-label explicit-list
      scenarios.

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `git ls-remote` assertions fail in tests | The mock `git` command does not handle the expected `ls-remote --heads origin <branch>` shape | Update the mock to match the exact command form used by the resolver. |
| Resolver tests call a mutating `gh` command | New code used a tracker mutation while resolving base branch | Remove the mutation; base resolution must remain read-only. |
| Bounded prelude summary omits fallback warning | Warning data is emitted by the resolver but not forwarded by `run-bounded-prelude.sh` | Add warning lines to the confirmation summary generation. |
| Workflow-hub tests fail branch validation | Product implementation branch was validated against the hub remote | Preserve repository-mode ownership semantics and defer validation when the product remote is not selected in this resolver. |

## Known Limitations

- This smoke test validates workflow CLI behavior with mocked issue and branch
  state; it does not remove real orphaned labels from GitHub issues.
